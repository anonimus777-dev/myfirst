# Бункер-бот — структура проекта

Это результат разбивки монолитного `bot.py` (~4000 строк) на модули по
структуре, которую вы показали на скриншотах.

## Запуск

```bash
pip install -r требования.txt
export BOT_TOKEN=ваш_токен_бота
python бот.py
```

## Структура

```
настройки.py              — токен, ID админов, все константы и справочники
                             (ROOMS_DATA, CROPS, PICKAXES, RP_COMMANDS и т.д.)
требования.txt             — зависимости (requirements.txt)
бот.py                     — точка входа: main(), регистрация хендлеров,
                             большие диспетчеры handle_message / handle_callback

вспомогательные/
    вспомогательные_функции.py   — форматирование чисел, расчёт цен/кулдаунов,
                                    карточные утилиты (fmt_smart, user_link, ...)
    проверки.py                  — require_bunker, user_exists, has_room
    сообщения.py                 — сборка текстов (build_bunker_text и т.п.)

база_данных/
    база.py       — init_db(), базовые CRUD-функции (get_user, get_rooms, ...)
    бункер.py     — прокачка комнат, пассивный доход, ремонт бункера
    пользователи.py — баланс, рейтинг, донат, бонусы, промокоды, статусы
    теплица.py    — выращивание и продажа урожая
    шахта.py      — добыча ресурсов, кирки

клавиатуры/
    общее.py         — базовые клавиатуры (back, no_bunker, donate)
    главное_меню.py  — клавиатура /help
    бункер.py        — клавиатуры комнат и /top
    активности.py    — RP-команды (обнять, поцеловать и т.д.)

сервисы/
    экономика.py   — бочки, казино (очко), крестики-нолики, бензин
    комнаты.py     — команды /room, /rooms, /buyroom, /letin
    пользователи.py — команды /start, /help, /me, /top
```

## Важно

1. **Файлы, для которых в исходном коде не было готовой функциональности —
   не создавались.** На скриншотах в `база_данных/`, `клавиатуры/` и
   `сервисы/` есть файлы под гильдии, кошек, пустошь, сад, скины,
   экспедиции — в `bot.py` соответствующего кода нет, поэтому эти файлы
   отсутствуют. Когда допишете эту функциональность, кладите её в файлы
   с такими названиями по аналогии с уже готовыми модулями.

2. **Найден и исправлен баг оригинала:** словарь `CROP_FORMS` создавался
   как *локальная* переменная внутри `handle_grow`, но использовался в
   `handle_message` — то есть в оригинальном монолитном файле это тоже
   было потенциальной ошибкой (просто могло не всплывать, если ветка
   кода не выполнялась). Вынес `CROP_FORMS` / `CROP_FORMS_ACC` в
   `настройки.py` как общие константы.

3. **Найден, но НЕ исправлен баг оригинала:** в `бот.py`, в обработчике
   callback-кнопки `room_currency_...`, используется необъявленная
   переменная `levels` (см. комментарий `⚠️` прямо в коде). Это была
   ошибка и в исходном `bot.py` — похоже, кусок кода про кулдаун
   апгрейда по ошибке попал не в ту ветку `if/elif`. Я не стал менять
   логику без вашего решения — отметил место комментарием.

4. В оригинале была строка `from unicodedata import category` дважды и
   `def fmt_smart(...)` определена дважды (вторая версия перекрывала
   первую). В разбивке оставлена только рабочая (вторая) версия
   `fmt_smart`, как и было в реальности при запуске оригинального файла.

5. Импорты между модулями я расставил вручную и проверил через
   `pyflakes` — весь проект успешно импортируется. Но учитывая объём
   переноса (~4000 строк, ~100 функций), рекомендую прогнать бота в
   тестовой среде перед продакшеном.
